## 合计与结论

- **static**：模型纯耗时 117.06s/次，13362.0 token/次，3.0 步，3.0 次模型调用，必备内容命中 4/4
- **dynamic**：模型纯耗时 145.37s/次，20828.5 token/次，2.25 步，3.25 次模型调用，必备内容命中 4/4

动态相对静态的 token 差：**+7466/次（+55.9%）**；模型调用次数差：**+0.2 次/次**。
token 差为正表示动态更贵。规划调用的成本就体现在这两个差值里；
但只有「必备内容命中」也持平或更高时，这个成本才是可接受的。

这张表才是能下判断的地方：**合计的 token 差会把难度差异平均掉**。看两件事——
「动态把它拆成了几步」，以及「花掉这些 token 换来的交付物是更长还是更短」。
一个拆成多步、token 数倍、交付物却更短的任务，就是这一轮动态没有收益的证据。

## 怎么读这份结果

- **墙钟时间这一列读不得**：里面混着网关节流的强制等待，`节流等待` 列是它的可解释部分，`模型纯耗时` 才是模型侧的真实开销。token 与调用次数不受节流影响，它们才是两个模式之间可比的口径。
- 单点任务上动态**必然**更贵：多一次规划调用，产出却不会更好。这类任务是判断「动态值不值得开」的下限。
- 只有「需要两路独立收集再合并」这类任务，静态三步图在结构上做不到，动态才可能出现真正的净收益；`two_independent_sources` 就是为这一点准备的。
- 必备内容命中是**弱判据**（只看关键词是否出现），它只能挡住明显的答非所问，不能替代人工读一遍交付物。
- 采样次数少时结论不稳（模型输出长度本身抖动很大），`--repeat` 调大再看趋势。

## 本轮结论（人工读表后补记，重跑脚本会覆盖本节）

把四行任务分开看，结论比合计那一栏清楚得多：

1. **合计口径是负的**：动态 +7466 token/次（**+55.9%**）、+0.2 次调用/次，而「必备内容命中」
   两边都是 4/4。等成本换等质量，就是没有净收益。
2. **动态的「省」发生在它不做三步的时候**。`single_question`（-72.3%）与
   `collect_then_summarize`（-51.2%）上，规划节点把计划收敛成 **1 步**——它等于在说
   「这个任务不值得走收集→分析→报告」。这确实省钱了，但省下的钱**不是动态编排的功劳**：
   给静态链路加一条「简单任务跳过 collect」的规则，成本更低（连规划调用都不用）。
3. **动态的「贵」发生在它真正拆开的时候，而且没换来产出**。被寄予期望的
   `two_independent_sources`（需要两路独立收集再合并）上，动态确实拆成了 4 步，
   但代价是 **43208 token vs 静态 16413（+163.3%）**，而交付物**从 2610 字缩到 736 字**。
   更贵、更多步、产出更短——这是这一轮最直接的反面证据。
4. **唯一「多钱多货」的一处**：`analysis_only` 动态 token +40.5%、交付物从 3697 涨到 6431 字。
   但「更长」不等于「更好」，而且它的步数与静态相同（都是 3 步），说明这更像模型那一次
   写得更长，不是编排结构带来的差异。

**因此在这 4 个任务、单轮采样的样本上，动态编排的净收益是负的。** 它目前唯一可复现的好处
是「对简单任务少做几步」，而这不需要动态编排。所以：

- **不建议在本轮之后打开 `AGENT_ORCHESTRATION_MODE=dynamic`**（默认仍是 `static`）。
- 档 3（并行 / 聚合 / 反思循环）的**前置条件仍未满足**：现在有数了，而数说「先别加」。
  下一步该做的不是加并行，而是先把评测集做大（更多任务 + 参考输出 + 多轮采样），
  再看这几条结论是否站得住。
- 「必备内容命中」是弱判据（只看关键词出现与否），它只能挡住答非所问。上面第 3、4 条
  关于交付物长短的观察，**建议人工读一遍那几份交付物**再决定要不要推翻。
