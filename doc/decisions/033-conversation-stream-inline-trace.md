# ADR-033: 对话流执行过程改成内联折叠（网页 AI 思维链形态）

状态：已接受

## 背景

ADR-031 把对话流升为第四个视图面，并规定执行过程做成一张卡片（`.run-activity`）插在
提问与答复之间：卡片头部报任务终态与进度，中间一块「任务分配」，下面每个阶段一个带边框
的折叠块，展开后是三段小标题（分配到的任务 / 执行轨迹 / 阶段产出）。

形态本身工作正常，但**用户 2026-09-22 的反馈是「效果不太对」**：要的是网页 AI 那种
思维链观感——**只有一行文本可以展开/收起、融合在输出里、不突兀**，而不是一块专门的
卡片区域。回头看，「突兀」有三个具体来源：

1. **外壳把过程从消息里割了出来。** 边框 + 圆角 + 底色让这块内容看起来像「另一个面板」
   插在对话中间，而不是这条回复的一部分。
2. **「任务分配」重复了。** 同一份数据（`checkpoint.plan_rationale` + 分配顺序）在
   ADR-032 之后已由协作画布的 planner「任务分配」节点承载，对话流里再画一遍是重复。
3. **层层折叠加起来比正文还重。** 默认状态下就已经是一张满是分隔线与三段小标题的卡片。

## 决策

### 1. 形态：一行灰字，点开才铺开

外层是**一个纯文本按钮**（`.run-chain-head`），没有边框、没有底色：

| 状态 | 那一行写的 |
| --- | --- |
| 运行中 | `{角色名} 正在执行 · T 次工具调用 · 用时 X` |
| 已完成 | `已执行 N 步 · T 次工具调用 · 用时 X`（静态链路写「N 个阶段」） |
| 失败 / 已取消 | `任务执行失败 · 已完成 M 步 · 用时 X` |
| 排队中 / 已暂停 | 同口径，用状态文字 |

**跑完默认收起**（网页 AI 也是这个行为），**运行中默认摊开**。展开后逐个 Agent 列出，
每一步**仍可单独点开**看它调了什么工具、产出了什么。层级靠缩进与一条左侧细线表达，
不靠容器。

### 2. 措辞不叫「思考」

**这是本次最容易做错的一处。** 网页 AI 那一行写的是「已思考（用时 X 秒）」，照搬最省事，
但本平台落盘的只有 ReAct 链里的**行动与结论**（`tool_calls` + `content`），模型内部的
隐藏推理既没落盘、服务端也不提供（`doc/api.md` §5.17、`app/api/stage_trace.py`）。
叫它「思考」会让读的人以为下面铺开的是模型的推理过程——**那正是 ADR-031 §5 要避免的**。
因此写「已执行 N 步」「{角色名} 正在执行」：**形态照搬网页 AI，措辞不照搬**。

### 3. 「用时」是算出来的，不是编的

起点取 `created_at`（真实落库时间），终态取 `completed_at`（缺了退 `updated_at`），
运行中取当下并从 `created_at` 起本地走秒。任一端解析不出来就**不显示这一项**，
而不是摆一个估出来的数字。

### 4. 删掉「任务分配」块

协作画布的 planner 节点已承载同一份数据（ADR-032）。同一份数据在两个面各画一遍，
正是「突兀」的来源。`.run-assignment` 一整组规则随之删除。

### 5. 折叠块本身压平，`tone` 一并删除

`components/Disclosure.tsx` 的唯一使用方就是这里，所以直接把它做成纯文本行，
并删除按状态给左侧竖条着色的 `tone` 属性与 `.disclosure.tone-*` 一组规则——
留着就是死样式。状态改由摘要行里的 `.run-step-state` 文字承担。

### 6. 修订 ADR-031，其余全部保留

**保留**：插入点（提问之后、答复之前）、Markdown 正文渲染、渐进揭示的边界、
三段小标题与执行台弹窗逐字一致、不伪造思维链、轨迹渲染只有一份实现、轨迹缺席不留白、
说明性文字摆在折叠之外。

**修订**：ADR-031 §4 里「做成卡片」的形态描述，以及「摘要行必须写清谁 / 什么状态 /
动了几次工具」这条——它移到**展开后每步那一行**上；外层那一行改为写
**步数 / 工具次数 / 用时**（「谁」由运行态的「{角色名} 正在执行」给出，终态一次点击可得）。

## 备选方案

- **照搬「已思考（用时 X 秒）」措辞。** 否决：展示的是工具调用链而不是模型推理，这么写会
  误导读的人；要真展示推理得先让 C 线把 reasoning 落库——ADR-031 已把这件事明确划归
  「先有真实数据再谈呈现」，不该由前端先行用词解决。
- **保留卡片外壳，只删「任务分配」块。** 否决：用户反馈的第一条就是「专门卡片区域」，
  外壳正是被指的那个东西；只删分配块等于没回答反馈。
- **跑完保持展开。** 否决：与网页 AI 的行为不一致，且回看历史时整屏都是过程。
- **每步各占一行、不设外层总行。** 否决：折叠状态下仍占 N 行，比参考形态重。不过
  「哪一步在跑」这个信号不能丢——所以运行态把它写进外层那一行。

- 改动前端文件：`workspace/RunActivity.tsx`（形态重写）、`components/Disclosure.tsx`

  「跑完收成一行：步数 / 工具次数 / 用时」（fixture 的 `created_at` / `completed_at` 正好
  差 30 秒，能钉死到字符串）、「跑完默认收起」「内联形态没有卡片外壳，也不再重复画布上的

- 「用时」用到的 `created_at` / `updated_at` / `completed_at` 都是既有字段，未新增接口字段。
