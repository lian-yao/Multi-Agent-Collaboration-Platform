# ADR-015: 取消配置写入的管理员令牌限制

状态：已接受

## 背景

ADR-013 决策 5 为配置写接口引入了 fail-closed 的权限边界：请求头 `X-Admin-Token`
必须等于服务端环境变量 `ADMIN_TOKEN`，`ADMIN_TOKEN` 未配置时一律 `403`。
ADR-014 把这个边界沿用到了新增的 `PUT /api/v1/config/provider`。

实际使用中的问题：平台是单机/内网演示部署，操作者即管理员；令牌带来的是
「先配一次环境变量、再在页面上重复输入一次」的额外步骤，而它并不防御真正的威胁
——能访问该接口的人通常也能访问宿主机与配置。

2026-09-15 用户决定：**不需要这个限制**。

## 决策

1. **删除令牌校验**：移除 `ADMIN_TOKEN` / `X-Admin-Token` 与
   `app/api/main.py::_authorize_config_write`，`PATCH /api/v1/config/agents/{agent_id}`
   与 `PUT /api/v1/config/provider` 不再做写入鉴权，`app/config.py::AdminSettings`
   与 `get_admin_settings()` 一并删除。
2. **契约同步**：`doc/api.md` §1 错误码表与 §5.7、§5.8 的权限边界段落、错误码行同步
   删除；`403 CONFIG_WRITE_FORBIDDEN` 不再是这两个接口的返回码。
3. **前端同步**：工作台「工具与配置」页删除管理员令牌输入框与 403 分支，保存只发送
   配置字段本身。
4. **边界改由网络与部署保证**（替代原令牌边界）：配置写接口默认只应监听在
   本机或可信内网；`doc/deployment.md` 增加显式提示——**若把 API 暴露到公网，
   任何人都能改写模型端点与凭据**。

## 影响

- **安全姿态变化（明确接受）**：任何能访问 API 的调用方都能修改模型、接口地址与
  `api_key`。这不是遗漏，而是本期范围内的取舍；风险由部署网络边界承担。
- **ADR-013 决策 5 被本 ADR 取代**，其余决策（覆盖表、读时合并、写失败显式暴露、
  审计日志）继续有效；ADR-014 决策 6~9 与前端入口部分同步修订，其余不变。
- **部署文档**：删除 `ADMIN_TOKEN` 环境变量行与 compose 相关说明，改为网络边界提示。
  `deploy/compose.yaml` 本来就未透传该变量，因此无需改动。
- **测试**：`tests/integration/test_config_api.py` 与
  `tests/integration/test_provider_config_api.py` 中的 403 用例删除，改为断言
  「不携带任何令牌即可写入」；其余契约用例（422/503/200、脱敏、回退）保持不变。
- **回退路径**：将来若需要多租户或公网暴露，应重新引入鉴权，且优先级是**会话级身份
  或 API 网关**，而不是再退回到单一静态令牌——静态令牌无法区分调用方，也无法审计。
