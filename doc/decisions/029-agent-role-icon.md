# ADR-029: 角色图标按 `role` 解析，配置页与协作画布共用一处

状态：已接受

## 背景

「Agent 团队」页的角色卡片左上角有一个 34px 的方块，里面放的是**显示名的第一个字**
（`agent.name.slice(0, 1)` → 「信」「数」「报」）。用户评审的判定：

> agent 配置的 icon 似乎是默认显示名称的第一个文本？这样很丑，和协作画布图节点的机器人
> icon 保持一致，也添加一些可能会用到的 icon。

三个问题，逐条对应：

1. **单字方块认不出是谁。**「信」「数」「报」是显示名的碎片，不是符号；同一屏里三个方块
   要靠旁边的名字才能分辨，等于这个位置没有承担信息。
2. **同一个 Agent 在两处不同形。**协作画布（ADR-028）的 Agent 圆面画的是机器人（`Bot`），
   配置页画的是中文单字——同一个角色，两个页面，两种图形。
3. **没有可用的图标目录。**自定义角色（`role` 是自由文本，如 `summarizer`）除了首字之外
   没有任何可选的图形。

## 决策

### 1. 图标按 `role` 解析，不按显示名

判据是角色目录里的**稳定语义键** `role`（内置 `collector` / `analyst` / `reporter`，
自定义角色为自由文本键，见 `doc/api.md` §5.7）。显示名只作第二判据。

按显示名匹配会被一次改名带偏：把「信息收集 Agent」改叫「资料员」，图标就跟着换，
而它仍然是个收集角色。两轮扫（先 `role` 全表、再显示名全表）而不是把两者拼成一个串，
就是为了不让名字里的关键词压过 `role`。

### 2. 回退是机器人，不是字母

`fetch` 不到更贴切的语义时画 `Bot`——协作画布的 Agent 节点本来就画它。含义是
「没有更贴切的语义时就画通用 Agent」，而不是再退回一个字母块。

注意区分 Provider 侧的做法（`ProviderMark` 仍回退 `Monogram` 字母块）：那里回退的是
**真实品牌缩写**（「深度」），有辨识度；角色名首字没有这个性质。

### 3. 配置页与协作画布共用同一个解析器

`frontend/src/components/AgentGlyph.tsx` 是唯一的判断处，配置页的 `AgentRoleCard` /
`AgentTuningPanel` 与画布的 `NodeGlyph` 都调它。**同一个角色在两处必然同形**是结构性保证，
不是靠两边各自记得改——这正是背景里第 2 条的病根。

### 4. 状态优先于角色（只对画布）

画布的圆面图形按这个顺序决定：

| 顺序 | 条件 | 画什么 |
| --- | --- | --- |
| 1 | `failed` | `CircleAlert` |
| 2 | `paused` | `Pause` |
| 3 | `running` | `LoaderCircle`（转圈） |
| 4 | 其余 | 角色图标 |

执行中 / 失败 / 暂停是**人要立刻看见的信号**，不能被角色图标盖掉。配置页没有状态诉求，
直接画角色图标。

### 5. 关键词表即图标目录，顺序即优先级

`AGENT_ICON_RULES` 是一张 `[图标键, 关键词表]` 的有序表，**靠前的先匹配**，所以更具体的
关键词必须排在更宽泛的前面（`报告` 要排在 `信息` 前面，否则「信息报告 Agent」会被判成收集）。

当前 15 个键（含回退 `bot`）：`report` / `summary` / `write` / `translate` / `review` /
`plan` / `code` / `chart` / `compute` / `search` / `research` / `knowledge` / `converse` /
`media` / `bot`。键名取**语义名而不是图标名**，这样换图标（`chart` 从折线换柱状）不必动匹配规则。

加一张图标只要往表里加一行；键名同时是 `AGENT_ICON_GLYPHS` 的键。

## 备选方案

- **加一个后端 `icon` 字段让用户选。** 否决：要动 `agent_registry` 的库表结构与
  `doc/api.md` §5.7 的响应契约（属 B 的 `app/core/checkpoint.py`），而收益只是「换一张图」。
  当前按 `role` 解析已经能覆盖内置三角色与常见自定义角色，改动面小得多。
- **配置页一律画机器人（照抄画布），不做关键词表。** 否决：那就把「也添加一些可能会用到的
  icon」这条诉求丢了，而且画布上三个节点全是一样的机器人，等于没利用图形。
- **按 `role` 大小写或精确等值匹配。** 否决：自定义角色是自由文本，精确匹配等于只有内置
  三个有图标，其余全回退——等于没有目录。
- **配置页也按状态换图形。** 否决：角色卡片讲的是「这个角色怎么配」，卡片上的状态已经有
  `.cfg-agent-live`（当前阶段）与状态文案，圆面再抢一份就成了两处表达同一件事。

## 代价

- **多了一处需要维护的映射。** 新角色关键词不进表就回退机器人——不会画错，只是不够贴切。
  冒烟里有「图标键与图形一一对应」与「role 语义键决定图标」两条断言兜住键与图形的错配
  （错配是静默的：界面照常渲染，只是画了个不相干的图标）。
- **15 张图标进包**：`lucide-react` 按图标 tree-shake，JS 从 419.13 kB 增到 424.97 kB。
- **关键词表永远不完整。** 这是显式接受的：回退是机器人，不是空白。

## 教训

背景里的三条其实是同一件事的三种表现：**用一个位置承载「谁」，就必须给它一个可辨识的符号**。
单字方块在只有三五个角色时勉强能记住，但它既随显示名漂移（改名即换脸），又在另一个视图里
已经有了更好的答案（机器人）。两个视图画同一个对象时，「各画各的」是**默认会发生的**——
一致性要么由共同的解析器保证，要么就会慢慢消失。
