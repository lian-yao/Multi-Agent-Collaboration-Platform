# ADR-033：工作区沙箱（work_dir 的授权、档位与审批）

- 状态：已接受（**设计**；实现待排期，落地前不得按本文写代码）
- 日期：2026-09-23
- 相关：ADR-012（内置工具与沙箱）、ADR-021（多模态附件）、ADR-023（部署侧沙箱可用）、
  ADR-025（会话级只读文件工具）、ADR-034（出网策略）

## 背景

需求是「用户自选一个本地工作文件夹，Agent 的业务全部限定在该文件夹内，且对目录内拥有
增删改查权限；禁止访问该文件夹之外的本地文件」。而现状是：

- 平台**没有工作区概念**：Agent 能碰的文件只有会话附件（ADR-021 上传、ADR-025 只读读回），
  数据来自 `attachments` 表，不是磁盘上的一个目录；
- 沙箱容器**不挂任何宿主卷**，而且 ADR-025 把这条当成刻意决策写了下来；
- `app/sandbox/policy.py` 用模块白名单禁掉了 `open`、`import os` 等，沙箱里的代码
  **打不开任何文件**；
- Web UI 是 nginx 托管的静态前端，**拿不到宿主路径**：浏览器能给的只有
  `showDirectoryPicker()` 的句柄，它无法传给后端进程。

最后一条决定了很多事：在 Web UI 里「弹窗选本地文件夹」这个动作本身是做不到的，
必须先把它翻译成服务端能表达的东西。

## 决策

### 1. 授权单位是「宿主固定根 + 根内子目录」，不是任意宿主路径

宿主固定一个工作根（默认 `~/MacpWorkspace`，由 `WORKSPACE_ROOT` 指定），以 bind mount
挂进容器 `/workspace`。用户能"选"的是这个根**下面的子目录**，前端通过服务端的目录浏览
接口来选。

理由不是偏好，是约束：

- **bind mount 在容器创建时就固定**，运行期选一个宿主路径出来，容器里根本不存在的路径
  无从挂载；
- 浏览器给不了宿主路径（见上），要真正的原生对话框只能加桌面壳或让后端跑在用户本机，
  那是另一套产品形态。

因此「用户弹窗自选」在本项目里落地为：**`/workspace` 内的目录选择器**。要在部署层换根，
改 `WORKSPACE_ROOT` 并重建 backend——这是一次明确的部署动作，不是运行期开关。

### 2. 只有两档文件权限，且没有「工作区之外」这一档

| 档位 | Agent 能做 | 谁能设 |
| --- | --- | --- |
| `read_only`（**默认**） | 列目录、读正文；写类工具**不进工具集** | 所有人 |
| `workspace_write` | 工作区内新建 / 修改 / 删除 / 移动 | 所有人（用户在 UI 上显式提档） |

**不实现 `full_access`**。需求写明「禁止 Agent 访问、修改该文件夹之外的本地文件」，
再给一个普通用户可选的全盘档位，等于把安全边界换成用户开关；那正是本项目反复在修的
「假开关」的另一面（`doc/api.md` §5.11 对 `allowAutoExecution` 的处理是同一取向）。

将来若真需要让 Agent 看别处，正确做法是**在部署层换 `WORKSPACE_ROOT`**（管理员动作，
可审计、需要重建），而不是加一个界面开关。

### 3. 档位只能由人提升，Agent 没有提权通道

提档是**用户在 UI 上的操作**，不是 Agent 可以发起的请求。Agent 只能在自己的档位内行动；
越界访问**直接拒绝**（不是弹审批），并记审计。

理由：Agent 读进来的内容（网页、工作区里的文档）可以被提示注入操纵。若 Agent 能
「申请提权 → 弹卡片 → 用户点同意」，攻击面就从"绕过代码"变成"说服用户"，而卡片上写的
理由恰恰是攻击者控制的那段文本。拒绝越界 + 只允许人来提档，把这条链路掐掉。

### 4. 路径守卫是唯一入口，没有旁路

新增 `app/workspace/`，所有文件访问都过 `resolve_in_workspace(rel)`：

1. 拒绝绝对路径、`..`、空段、NUL；
2. `Path.resolve()` 展开符号链接后，断言工作区根是它的父目录（**符号链接指向外部一律拒绝**，
   包括工作区内被沙箱代码创建的链接）；
3. 拒绝特殊文件（设备、FIFO、socket）与超过限额的文件；
4. Windows 额外拒绝保留名（`CON`/`PRN`/`AUX`/`NUL`/`COM1`…）、UNC 路径与 NTFS 数据流
   （`file.txt:stream`）；
5. 每次操作**重新校验**，不能只校验父目录——`move` 的来源与目标各自都要过这一关。

> 实现口径（`app/workspace/paths.py`，2026-09-23）：第 4 条**不按平台分支**——容器里跑
> Linux、工作区内容却来自 Windows 宿主，按最严的一侧统一拒绝才能保证行为可预期；
> 另外整串首尾空白先 `strip()`，段内以空格或点结尾按 Windows 语义拒绝。

## 阶段 2 实现口径（2026-09-23）

写档位上线时按"能不能在没有人参与的情况下造成损失"把动作切了一刀：

**阶段 2 放开**（非破坏性）：`write_work_file`（**只能新建**）、`make_work_dir`、
`move_work_entry`（目标已存在时拒绝）。**阶段 3 才放开**：删除（软删除到 `.trash/`）、
覆盖已有文件、覆盖式移动。

理由是本 ADR §6 自己定的规则——删除与覆盖需要人工审批。先放开、之后再补审批，等于在
中间那段时间里让"审批"这条规则失效；宁可让模型先换个文件名，也不打开一个"没有审批的
覆盖"。相应地：只读档位下这三个工具**不出现在工具集里**（档位决定可用动作集合，而不是
出现了再报错），`overwrite=true` 在目标已存在时返回 409 `WORKSPACE_APPROVAL_REQUIRED`
并在文案里告诉模型改用新文件名。

## 阶段 3 实现口径（2026-09-23）：审批不做工作流级挂起

本文第 6 条原本写的是「命中审批时把该次执行置 `paused`、用户决策后 `resume`」。
实现时改成了**批准后重试同一调用**，理由与代价都记在这里：

- 真正的挂起需要阶段活动中途停下来等外部事件（Dapr 外部事件 + 恢复语义），那是编排层的
  改动，风险和收益不成比例；
- 审批的价值是"人看过之后才放行"，这一点用"批准一次、放行一次"就能拿到，而且**更强**：
  记录放行后置 `consumed`，不存在"批准过一次，以后都能覆盖"的长期授权；
- 代价是模型要多走一轮：第一次调用只会拿到带审批 id 的非重试错误，用户批准后需要它
  **重试同一调用**。因此错误文案必须写清"批准后重试同一调用、不批准不要重试"。

另外三条落地细节：`workspace_id` 参与匹配（否则 A 工作区的审批会放行 B 工作区的同名
文件）；同一个待决策目标反复请求复用同一条记录；超过 TTL 的 `pending` 置 `expired`
（不放行、不删记录）。会话/Workflow 级的 `paused` 仍可用于人为暂停，只是不再由审批触发。

工具集（会话级，按 ADR-025 的 `session_scoped_registry` 就地拼进本次执行，不进
`GET /api/v1/tools` 静态目录）：`list_work_files` / `read_work_file` /
`write_work_file` / `make_work_dir` / `move_work_entry` / `delete_work_entry`。

### 5. 会话绑定独立的子目录

一个会话绑定工作根下的 `sessions/<session_id>/`（可按会话再选子路径）。两个会话同时跑时
不共享可写目录，避免互相覆盖；需要共享时由用户显式选择同一个子目录。

### 6. 写操作要有配额、软删除与审批

- 单文件大小、单次写入字节数、目录条目数与目录总字节数四类配额，超限**拒绝并在错误里给出
  当前用量**（不是静默截断）；
- 删除进 `sessions/<id>/.trash/`，保留期后清理；覆盖已有文件必须显式 `overwrite=true`；
- **删除与覆盖需要人工审批**：命中时写 `approvals` 记录、把该次执行置 `paused`、前端弹
  审批卡片，用户允许或拒绝后 `resume`。这条链路复用既有的
  `POST /sessions/{id}/pause` / `resume`（`doc/api.md` §4.6 / §4.7）与 Workflow 的
  `paused` 状态，不新增挂起机制。

这也顺带把 ADR-026 里一直悬着的 `allowAutoExecution` 用起来——它的语义本来就是
「调用前需要人工确认」，此前没有审批环节所以只能不消费。

### 7. 沙箱代码可以直接读写 `/workspace`（**本决策推翻 ADR-025 的取舍**）

需求要求 Agent 对目录内增删改查，而 `code_execution` 是这个平台上真正干活的工具
（`pandas`、格式转换、批处理都靠它）。所以：

- 沙箱容器**挂载同一个工作根**（`/workspace`），可读可写；
- 沙箱策略里 `open`、`pathlib` 等**从禁止改为允许**，但 `socket` / `subprocess` /
  `ctypes` / `import os` 的越权面**保持禁止**（网络另由沙箱的 `network_enabled=false`
  与 ADR-034 控制）；
- 沙箱容器以**非 root** 运行（`SANDBOX_UID` / `SANDBOX_GID`），避免在宿主留下 root 属主的
  文件；根文件系统保持只读，`/tmp` 用 tmpfs；
- **绝不允许同一个容器同时拿到宿主 Docker socket 与宿主工作根**。当前架构里
  `/var/run/docker.sock` 挂在 backend（ADR-023），沙箱容器本身没有它——这条不变量要写进
  测试，任何一次改动把它打破都是安全回归。

ADR-025 当初拒绝挂卷的理由是「给沙箱挂宿主目录会叠加风险」。本决策接受这个风险，
但把范围收窄成「只挂一个专用工作根、非 root、无网、无 socket」，并明确**不要**把项目仓库
或平台数据目录当作 `WORKSPACE_ROOT`（`doc/deployment.md` 会写出这条禁令）。

## 备选方案

- **浏览器 File System Access API 选目录**：句柄只能在浏览器里用，后端拿不到路径，
  Agent 无法读写。否决。
- **后端原生目录对话框**（`tkinter` / PowerShell）：只在 backend 跑在用户本机时成立；
  一键部署是容器形态，对话框开在服务器上毫无意义。否决。
- **运行期重建容器以挂载任意宿主路径**：把「选文件夹」变成一次容器重建，且有权限与
  并发问题。否决。
- **只给沙箱挂只读工作区，写入走 backend 的文件工具**：更保守，但沙箱里的代码无法产出
  文件（只能把结果打到 stdout 再由工具写回），对真实任务不成立。作为**降级选项**保留：
  `WORKSPACE_SANDBOX_MOUNT=ro`。

## 代价（如实记录）

- **宿主固定根**：用户不能选任意路径，必须先（或由管理员）把根挂好。这是 Web UI 形态的
  固有代价，不是实现偷懒。
- **可写挂载让沙箱能往宿主目录写文件**：提示注入可以让 Agent 往工作区写一堆垃圾、
  或写一个诱导用户双击的可执行文件。缓解是配额、软删除、审批、审计，以及**平台自身不执行
  工作区里的任何内容**（不 import、不 shell、不自动打开）。
- **非 root 与 Windows 权限语义**：Docker Desktop 的 bind mount 在 Windows 上由虚拟文件
  系统承担，属主映射与 Linux 不同；`SANDBOX_UID/GID` 只在 Linux 宿主上真正生效，文档要写清。
- **配额是应用层而非文件系统级**：backend 崩溃或沙箱绕过工具直接写盘时，配额拦不住。
  真要硬上限得用文件系统配额或独立卷，本 ADR 不做。

## 验证（实现时按此测试）

- **路径逃逸表**（≥12 例）：`..`、绝对路径、符号链接指向根外、硬链接、Windows 保留名、
  UNC、NTFS 数据流、大小写差异、超长路径、NUL、空段、`move` 目标越界；
- **档位矩阵**：`read_only` 下写类工具不在工具集里；`workspace_write` 下六类操作可用；
  越界访问在两种档位下都被拒且记审计；
- **审批链路**：删除/覆盖 → `pending` → 允许则执行、拒绝则不执行，两条路径都能从
  `paused` 恢复；超时未决策的状态与清理规则确定；
- **沙箱读写**：沙箱代码在 `/workspace` 内建文件后，宿主能看到、属主正确、`open` 可用，
  但 `socket` / `subprocess` / 工作区外路径仍被拒；
- **不变量测试**：沙箱容器**没有**宿主机 Docker socket 挂载（防止将来被改坏）。
