# ADR-035: 本地服务形态——授权单位是「用户当场选的文件夹」

- 状态：已接受（设计）；实现随后排期
- 日期：2026-09-23
- 相关：ADR-033（工作区沙箱：固定根 + 根内子目录）、ADR-025（会话级文件工具）、
  ADR-015（本机无令牌）、ADR-034（出网策略，与本决策无关）

## 背景

使用者的原话是：**「读取文件夹改为默认宿主侧的文件，浏览器网页 ↔ 本地后端服务（localhost）
↔ 本机磁盘文件夹；后端程序负责读本地文件夹，浏览器只通过 HTTP 接口拿结果；浏览器不能直连
磁盘」**，并进一步定了范围与形态：**「用户可以在本地机器任意选择一个文件夹，然后在那个
文件夹下的所有文件都可以读写，但也只能在这个文件夹下面」**；**「把宿主直跑做成一键默认」**。

这条要求与 ADR-033 的选择正面冲突，但冲突的**前提**已经变了。ADR-033 §1 把授权单位定成
「宿主固定根 + 根内子目录」，理由是两条硬约束：

1. **bind mount 在容器创建时就固定**，运行期选一个宿主路径出来，容器里根本不存在的路径
   无从挂载；
2. **浏览器给不了宿主路径**，要真正的原生对话框只能加桌面壳或让后端跑在用户本机。

第 2 条里的后半句正是使用者现在要的形态：**后端跑在用户本机**。后端一旦直跑，
它看到的路径**就是**宿主路径，第 1 条不再成立（没有 bind mount 这层翻译）。
两次实测反馈——「为什么不能像附件一样选文件夹」「工作区没有选择文件夹位置功能」——
根因也是同一个：**授权单位不该由部署时的固定根决定，而该由用户当场选**。

## 决策

### 1. 授权单位 = 用户当场选定的一个宿主文件夹（绝对路径）

**不加列**：`workspaces.path` 在宿主形态下直接存**宿主绝对路径**（如 `D:\项目\2026`），
在容器形态下仍旧存相对路径——由 `WORKSPACE_SOURCE` 决定怎么解释。理由是少一次不可逆的
schema 变更：`ux_workspaces_path` 这条唯一约束已经在有数据的库上了，改成 `(root_path, path)`
要 drop/重建索引，而收益只是"一列只表达一种含义"。代价写清楚：

- 两种形态的 `path` 不能混用——**切形态会让旧登记解析失败**（宿主形态下相对路径不是绝对
  路径、容器形态下绝对路径被守卫拒绝），两边都**显式报错**，不静默当成另一层含义；
- 这与本 ADR「改根会让历史行失效」的既有代价同类：`WORKSPACE_ROOT` 换了也一样。

**不变量不变**：所有文件访问仍过 `resolve_in_workspace()`——只接受相对子路径、解析后必须
仍在根内、指向根外的符号链接一律拒绝。

差别只在「根从哪来」：过去是部署者写死的一个目录，现在是使用者当场选的那个文件夹。
**「只能在这个文件夹下面」这条边界一个字都没松**：放开的是**选根的自由度**，
不是根内路径的约束。

### 2. 两种形态，一个开关，行为分开判定

`WORKSPACE_SOURCE` 取 `host` / `container`；**代码默认 `host`**（使用者要的默认形态），
`deploy/compose.yaml` 显式设成 `container`。

| | `host`（默认，一键直跑） | `container`（保留） |
| --- | --- | --- |
| 后端位置 | 宿主进程，绑 `127.0.0.1:8000` | 容器，只接 internal 网 |
| 根从哪来 | 用户当场选的绝对路径 → `root_path` | `WORKSPACE_HOST_ROOT` 挂 `/workspace` + 相对 `path` |
| 目录浏览 | `GET /host/tree` 可浏览宿主任意绝对路径（**只读、仅目录**） | 仅根内：`GET /workspace-root/tree` |
| 默认档位 | `workspace_write` | `read_only`（不变） |

**不能一刀切**：容器里 `/workspace` 之外的宿主路径既不存在、也无从挂载，所以浏览范围必须按
形态判定，而不是「把限制去掉」。

### 3. 接口

- `GET /api/v1/host/tree?path=<绝对路径>&depth=1`（`host` 形态专用）：**只读、只列目录**，
  附盘符/家目录入口。不返回文件内容——文件正文仍只走既有的工作区工具与接口。
  `container` 形态返回 503 `WORKSPACE_HOST_BROWSE_DISABLED`。
- `POST /api/v1/workspaces` 增加 `root_path`；`path` 的含义收窄为**该根内的相对子路径**
  （默认空串＝就是用户选的那个文件夹）。
- 上一轮刚加的 `GET /api/v1/workspace-root/tree` 保留给容器形态的「根内选位置」；
  `host` 形态下前端只用 `host/tree`，避免两个基准并存。

### 4. 默认可写，但破坏性动作仍要人工审批

使用者的要求是「那个文件夹下的所有文件都可以读写」，所以 `host` 形态登记时**默认
`workspace_write`**（ADR-033 §2 的「默认只读」只保留在容器形态）。ADR-033 §6 的
**覆盖 / 删除需人工审批不动**：那是把误删做成不可逆之前的最后一道闸，与"能不能写"是两件事。

### 5. 安全边界与代价（必读）

- **只绑 `127.0.0.1`**：`host/tree` 是「读整机目录结构」的能力，绝不发布到不可信网络；
- **单人单机前提**：沿用 ADR-015 的口径，本机 HTTP 无令牌、无鉴权。多用户或公网部署时
  本形态作废，必须回到容器形态 + 根内子目录；
- **只读浏览**：浏览接口不返回文件正文，正文只经工具与审批链路；
- **拒绝选平台自身源码目录**：沙箱对工作区可写，而仓库里是平台自己的源码（沿用
  `pick_work_dir.ps1` 的同一条禁令，异常信息里说明原因）；
- 容器形态下 `host/tree` **关闭**，不给"看起来能选、其实是容器里不存在的路径"的假入口。

### 6. 一键直跑

`scripts/start_local.ps1`：compose 只起 Redis 与 PostgreSQL（Jaeger/Prometheus 可选），
`daprd` 复用 `scripts/run_local_sidecar.ps1`，后端 `uv run python -m app.workflows.worker`
（绑 `127.0.0.1:8000`），前端 `npm run dev`（`/api` 反代到 `:8000`）。README 与
`doc/deployment.md` 的默认入口改成本形态，容器形态作为「部署 / 演示」的备选保留。

## 备选方案

- **桌面壳（Tauri / Electron）**：能拿原生对话框与真实路径。否决：为一件 HTTP 已经能做到的
  事引入第二套前端壳与构建链，维护面翻倍。
- **仍然固定根，只把根选得更大（`WORKSPACE_BROWSE=all`）**：否决：使用者要的是"当场选一个
  文件夹"，不是"把固定根换成整机"——后者既没有边界感，也解释不了"只能在这个文件夹下面"。
- **让浏览器用 `window.showDirectoryPicker()` 拿目录句柄**：仍然否决（ADR-033 的原判不变）：
  句柄只在浏览器里有效，服务端 Agent 用不上。

## 影响

- `app/workspace/config.py`：形态开关、浏览开关、宿主形态下的默认值；
- `app/workspace/paths.py`：新增宿主目录解析（绝对路径、必须存在且是目录、拒绝平台源码目录）；
- `app/workspace/service.py`：`create_workspace()` 按形态解释 `path`，新增
  `workspace_base()` 统一解析生效根；`LocalWorkspaceSource.root()` 走同一条；
- `app/core/checkpoint.py`：**只加列**（`root_path` 不引入；`path` 语义按形态解释），
  `doc/data-model.md` §3.3 同步说明两种形态；
- `app/api/main.py`：`GET /api/v1/host/tree`、`POST /workspaces` 在宿主形态下收绝对 `path`；
- `frontend/`：选择器按形态切换——`host` 形态显示真实路径（盘符 / 家目录入口），
  选中即登记（默认可写）；
- `scripts/start_local.ps1`（新）、`doc/deployment.md`、`README.md`；
- 与 ADR-025 的会话级工具集、ADR-034 的出网策略无交互。
