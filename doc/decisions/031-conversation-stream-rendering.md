# ADR-031: 对话流升为第四个视图面（Markdown 正文 / 渐进揭示 / 内联执行轨迹）

状态：已接受

## 背景

ADR-018 定下「工作台三块视图职责互斥，不重复渲染同一份数据」：执行台弹窗管单个 Agent 的
轨迹、任务协作侧栏管任务级、任务记录页管逐条明细。三块都成立，但**对话流本身没有被纳入
这套分工**，于是出现了两处具体问题：

1. **正文是纯文本。** `App.tsx::MessageBubble` 把 `message.content` 直接塞进 `<p>`。
   模型是按 Markdown 组织输出的——`## 标题`、`**加粗**`、`- 列表`、`| 表格 |`、围栏代码块。
   浏览器不解析这些记号，于是它们**原样显示**。报告越长记号越多，满屏星号与竖线。
   这不是「排版不好看」，是**模型表达的结构全部丢失**：读的人得自己在脑子里把 Markdown
   解析一遍。用户 2026-09-21 的反馈是「很多符号并没有相应渲染，效果不是很好」。

2. **过程与结果被拆到不同面板。** 执行轨迹只在执行台弹窗（§5.17）与记录页里，对话流
   只剩一行「任务执行中 · 可在下方查看执行状态」（`.run-event`）。要在对话里理解
   「这一步为什么得出这个结论」，得自己跑到另一块面板里对时间线。主流 Agent 的对话流
   恰恰是把「它调了什么工具、结果是什么」铺在消息之间——**在结果出现的那个位置**给过程。
   用户反馈里的「缺少在相应位置展开/收起思维链，还有具体工具输出的地方」指的就是这件事。

## 决策

### 1. 对话流升为第四个面，边界按**时间**重划而不是按数据

ADR-018 的「不重复渲染同一份数据」在别处成立，在这里要修正：重复本身不是问题，
**错位**才是。四个面回答的是**同一批只读数据在四个时间面上的问题**：

| 视图 | 回答什么 | 时间面 |
| --- | --- | --- |
| **对话流**（`.run-activity`） | 这一次执行**当下**跑到哪、调了什么、拿到了什么、产出了什么 | 进行中 |
| Agent 执行台弹窗（§5.17） | 单步的**完整**轨迹，含上游输入原文与截断标记 | 跑完之后回看 |
| 任务协作侧栏 | 任务级整体状态、协作画布、用量 | 任务级 |
| 任务记录页 | 跨任务的逐条工具调用与采样明细 | 审计 |

四个面都**只读**同一批服务端数据（§5.17 / §5.5），谁都不写、不缓存，因此不存在
「以哪一份为准」。ADR-018 决策 2 与决策 3 的结论（弹窗入口由执行台卡片承担、
节点点击不跳弹窗、侧栏不嵌 `WorkflowInspection`）**全部保持**。

### 2. 消息正文一律走 Markdown 渲染（GFM）

`components/Markdown.tsx`：标题、加粗、斜体、有序/无序列表、任务列表、表格、引用、
分隔线、围栏代码块与行内代码、链接、图片。

- **不挂 `rehype-raw`。** `react-markdown` 默认不解析裸 HTML，因此模型输出不会变成 DOM。
  这条要保住——为「支持 HTML」去挂 `rehype-raw` 等于把模型输出当 DOM 执行。
- **代码块不引高亮库。** 语言名留在 `data-lang` 上由 CSS 画角标。这里要的是
  「看得出来这是代码」，不是编辑器级着色；着色器会再拖进一套主题与解析器。
- **表格自带横向滚动容器**：让整段正文一起滚，会把上面的段落也推出视野。
- **外链新开页**并带 `rel="noreferrer noopener"`，不把当前会话导航掉。

### 3. 渐进揭示是**呈现效果，不是流式传输**

`components/useStreamText.ts` 把**已经拿到的**正文按帧逐步显示出来。必须写清它的边界：

- 后端**没有**事件流（`app/api` 里 `EventSourceResponse` / `StreamingResponse` 零命中）；
  助手正文是工作流走到终态时一次性落库的（`app/workflows/pipeline.py::finalize_activity`
  → `upsert_message`），前端靠 2 秒轮询拿到它。因此**不得**据此宣称「正在逐 token 接收」。
- 长文按**总时长**反推步长（下限 320ms、上限 1800ms），不按「每帧固定几个字」：报告动辄
  数千字，固定步长会让一篇长文打十几秒，读的人以为页面卡住了。
- **只对本次会话新到达的消息播放**（`App.tsx` 的 `revealed` 集合）。历史会话整屏逐字
  重放，会让人以为任务在重新执行——那是把呈现效果误当成执行进度。
- **非浏览器环境**（`renderToStaticMarkup`）与 **`prefers-reduced-motion: reduce`**
  一律降级为立即全文。前者不跑 effect，写入惰性初值时若给 0 就会渲染出空正文。

### 4. 执行活动卡片插在**提问之后、答复之前**

`workspace/RunActivity.tsx`，由 `reportIndex`（按 `agent_run_id` 找报告消息）定位插入点。
过程要出现在结果的**上一个位置**；排在整段对话末尾会看起来像另一个任务。

- 逐步轨迹按 §5.17 如实呈现，三段小标题与执行台弹窗**逐字一致**
  （**分配到的任务 → 执行轨迹 → 阶段产出**；弹窗的 `tool_calls` 即「推理 → 行动 → 观察 → 结论」
  里的行动与观察）。同一份字段在两处用两套词，读的人会以为它们是两件事——这是本仓库反复
  要避免的漂移，因此冒烟里同时断言两条渲染路径都带这三个词。
- 与弹窗的唯一差别：**根步骤这里不铺输入原文**。用户的原始任务就在上方那条用户消息里，
  重复一遍是噪音；弹窗是独立窗口，缺了它就读不到上下文。
- **正在跑的那一步默认摊开**，跑完的收成一行；用户手动拨过的开关不被自动规则顶回去。
- **摘要行必须仍写清「谁 / 什么状态 / 动了几次工具」**——否则收起就等于信息丢失。
- 轨迹缺席时转述服务端给的具体原因（四种原因指向四种不同的下一步动作），**不留白**；
  「整条链路都没有轨迹」（动态编排）的原因只说一次，不逐步重复。

### 5. 不伪造思维链

编排层落盘的是「推理 → 行动 → 观察 → 结论」里的**行动与结论**（`tool_calls` + `content`），
模型内部的隐藏推理既没落盘、服务端也不提供（`app/api/stage_trace.py` 模块注释、
`doc/api.md` §5.17、`doc/testing.md` 同口径，且**有断言在测这句话**）。
对话流按真实的 ReAct 行动链呈现，**不编造中间过程**。

### 6. 轨迹渲染只有一份实现

「一次工具调用」这一段抽到 `workspace/TraceParts.tsx::ToolCallBlock`，执行台弹窗与对话流
内联轨迹共用。两处各写一份必然漂移——最典型的漂移是「弹窗标了『已截断』、对话流把预览
当成全部」，读的人据此得出错误结论。

### 7. 依赖与产物

新增 `react-markdown@^10.1.0` + `remark-gfm@^4.0.1`（前端 `package.json`，不涉及 Python
依赖清单）。它们会连整棵 `micromark` 解析器一起进来，实测主包 402 kB → 589 kB，
**越过 Vite 的 500 kB 警戒线**，因此在 `vite.config.ts` 里把这一栈拆成独立 chunk
（拆完 422 kB + 166 kB，警戒线消除）。拆分依据是「这堆包只在渲染消息正文时用到」，
不是「太大就拆」——再往里塞别的依赖会把这层语义冲淡。

## 备选方案

- **保持纯文本正文。** 否决：模型的结构表达全部丢失，这是功能缺陷而非观感问题。
- **自研零依赖的 Markdown 渲染器。** 否决：GFM 的边界情况（嵌套列表与任务列表混排、
  表格对齐、代码围栏与行内代码的区分、链接内的转义）靠手写只会长期欠债；
  成熟库在这件事上就是更可靠。
- **在后端开 SSE，做真正的流式。** 暂缓（不是否决）：需要一个只读事件流端点，且要
  `app/workflows` 在阶段推进与工具调用发生时发布事件——跨到 B 线。而且即便做了，
  **LLM 逐 token 输出仍然拿不到**：生产链路是 Dapr 活动逐步手串（见
  `doc/dapr-integration.md`），活动边界内不向客户端推增量。所以「真流式」的现实上限是
  「按阶段/工具粒度推送」，与本轮做的前端渐进揭示相比，用户观感提升有限而改动量大得多。
- **把模型 reasoning 落盘，展示真正的思维链。** 否决（本轮）：跨 A/B/C 三线——需要
  采集侧落库、`app/core/checkpoint.py` 加字段、编排层透传，并修改 ADR-018、§5.17 与
  `doc/testing.md`（现有一条断言在测「说清隐藏推理没有落盘，不假装有思维链」）。
  排序上这属于「先有真实数据再谈呈现」，不该由前端先行。
- **保留 `.run-event` 一行文本，过程只留在弹窗。** 否决：那正是「过程与结果被拆散」
  的原状。

    `doc/testing.md` 中「不伪造思维链」那条断言。
