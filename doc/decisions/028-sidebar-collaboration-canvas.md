# ADR-028: 协作侧栏是「Agent 的配置与用量画布」，执行轨迹归执行台

状态：已接受

> **同日修订（2026-09-21）**：侧栏第一版把节点做成了**竖向堆叠的 Agent 卡片列表**，
> 用户评审的判定是「当前根本就不是画布」。本轮改为 SVG 节点图（决策 1、3 的呈现方式重写，
> 新增决策 7），决策 2、4、5、6 不变。教训记在决策 7 的末尾。

## 背景

ADR-018 把工作台的视图拆成三块（执行台 / 协作侧栏 / 记录页），但**侧栏那块装错了内容**：
它展示的是「协作链路」——每一步走到哪、等谁、跑到哪一步了，而同一件事执行台的卡片与
弹窗已经在说。用户的反馈很直接：

> 右侧栏的 agent 卡片，应该是记录 agent 的参数、token 这些了，和 agent 执行台不一样。

也就是说，ADR-018 解决了「三块视图不要重复渲染同一份数据」，但没有回答侧栏究竟该回答哪个问题。
用户每打开一次侧栏，看到的都是「进度」——而进度在执行台上一眼就能看到。

第二个洞是**回看能力**：一个会话里用户可能提交多次任务，每次都是一条独立的协作工作流。
此前界面上只有「当前这一次」，历史那几次连入口都没有，更没有「这次是哪次对话」的概念。

第三个洞是**Token 没有归到 Agent 头上**。ADR-018 的「影响」里写着
「依赖 C 的采集侧在 `metrics.labels` 里稳定写入 `agent_id`；前端已按该 label 分组，
缺失时退化为『任务级』」——这条假设是错的（见「决策 6」），而且照它实现出来的界面看起来
像「数据丢了」，实际是**读法错了**。

## 决策

### 1. 侧栏的「协作链路」改为「协作画布」，节点回答「这个 Agent 是用什么跑的」

节点是**圆形 Agent 节点**（`frontend/src/workspace/GraphCanvas.tsx`），圆面只放一个角色图标，
圆下方两行小标签写**名字**与**`模型 · Token`**——圆里放不下的信息必须出来，否则「记参数、
Token」这个诉求在图上根本看不见。完整的生效参数表、分配到的任务、阶段产出、工具明细
进悬停面板（决策 5）。

画布的首尾各有一个**端子**：`任务` 与 `交付`。它们不是装饰——「任务从哪进来、结果从哪出去」
是这张图与一张普通进度条的区别。

分工因此变成三句话（`doc/api.md` §7）：

| 视图 | 回答的问题 | 数据来源 |
| --- | --- | --- |
| 执行台卡片 / 弹窗 | 它**干到哪了**、收到了什么、调了什么、产出了什么 | `checkpoint` + §5.17 |
| 协作侧栏 / 全屏画布 | 它是**用什么跑的** | 角色配置 + §5.5 采样 + §5.18 |
| 任务记录页 | 逐条明细 | §5.4 / §5.5 / §5.6 |

侧栏与全屏**共用同一份布局与同一套渲染**（`CollaborationCanvas` 的 `dense` 开关），
只换密度：侧栏窄，只回答「谁跟谁、走到哪了」；全屏宽，连线才挂得上工具链胶囊。
各自从 props 现场推一遍布局，两处的「谁在第几步」迟早会分叉。

### 2. 侧栏节点**不是**执行轨迹的入口

ADR-018 的弹窗入口保持不变，仍由**执行台卡片**承担。画布上的节点点了不跳弹窗：
两块视图都能点进同一份轨迹，就又混成一个了。冒险的是"少一个入口"，实际省掉的是
"用户分不清自己在看哪一块"。

### 3. 连线记录**上游**这一步动过的工具，挂在边上而不是节点里

`A ——calculator ×1——> B` 读作「A 用计算器算出结果，交给 B」。用户要看的是
**这条数据是怎么被加工出来的**，所以工具属于"边"而不是"点"：画布把工具链画成**连线上的
一枚胶囊**，悬停它看入参出参。
计数**一律写出来**（含 `×1`）：只在多于一次时写数字会得到 `web_search ×3、sql_query`
这种半截话，读者无从判断后者调了几次。
没有工具就不画胶囊——空标签只是噪声。

### 4. 新增只读接口 §5.18 与全屏画布，给每次对话一个编号

`GET /api/v1/sessions/{session_id}/workflows` 按 `created_at` **升序**返回该会话的每一条
协作工作流，**编号 = 列表下标 + 1**。升序不是风格而是契约：倒序会让「对话 1」在下一次
提交后变成原来的「对话 2」，用户回看时点按的对话整体错位。存储层只提供升序读法
（`app/core/checkpoint.py::list_workflows_for_session`），接口不做二次排序。

侧栏给「展开全屏画布」入口（`frontend/src/workspace/CollabCanvas.tsx`）：`position: fixed`
覆盖层（要逃出 `.inspector` 的 `absolute; overflow:auto`），Esc 关闭，顶部是 `对话 1 / 2 / 3`。
选中非当前对话时，轨迹与用量按**那一份** Workflow 单独取（§5.17 + §5.5），不复用侧栏那一份
——复用会让「对话 1」显示成「对话 2」的数据。§5.18 只在画布打开时请求；拉不到就退化成
「只有当前这一次对话」，不报错空白。

### 5. 悬停详情用 CSS `:hover` / `:focus-within`，不用 JS 状态

参数全表、Token、分配到的任务、阶段产出、连线的入参出参都常驻 DOM，靠 CSS 控制显隐。
理由是**可验证**：JS 状态驱动的浮层在离屏静态渲染里永远是空的，冒烟测不到内容；
CSS 驱动则键盘可达、能被断言（否则这类"只有真机才看得见"的部分每次改动都要人工回归）。

### 6. 修正 ADR-018 的一条错误假设：Token 归属走 `role`，不走 `agent_id`

采样标签里**没有 `agent_id`**。编排层两条链路调 `observed_stage(...)` 时都只传 `role`
（`app/orchestration/pipeline_graph.py`、`dynamic_graph.py`），落地标签是
`workflow_id` / `stage` / `role`（Token 另有 `model`，阶段另有 `status`）。
`role` 与 Agent 目录的 `id` 同值（collector / analyst / reporter）。

原来只认 `agent_id` 的读法会让三个 Agent 的 Token 全部退到 `model` 一层、合并成一个
`gpt-5.5` 分组——界面上看就是「Token 没按 Agent 记」。归集顺序改为
**`agent_id` → `role` → `model` → 任务级**。`doc/api.md` §5.5 原文写的「可选 agent_id/model」
是同一处漂移，已一并改正。

**采样里出现 `role` 却不用它，比少一个字段更糟——数据在，是读法错了。**

### 7. 画法：SVG 像素坐标系 + 绝对定位圆节点，照 `Jasper-zh/Multi-Agent-Playground` 的 `GraphViewer.vue`

用户给的参考实现是 Vue 的，思路可以直接搬：**同一个盒子里**，节点是绝对定位的圆形 `div`，
边是**同尺寸** SVG 里的三次贝塞尔 `<path>`；两端各自退到圆周的上下极点，箭头才不会被节点
盖住、也不会斜着扎上来。灰虚线 = 要走的边，蓝实线 = 已经走通的边——进度靠颜色区分，
不靠文字说明。

四条落地时踩出来的规矩：

1. **SVG 的 `viewBox` 必须等于元素的像素尺寸**（`preserveAspectRatio="none"`），坐标系才和
   节点定位的 `left/top` 是同一套。靠百分比缩放会让圆变成椭圆、箭头被拉歪。
2. **量不到尺寸也要能画**。离屏冒烟与 SSR 里 `getBoundingClientRect()` 返回 0，此时退回
   默认宽度继续算布局——视图本体因此能被静态渲染直接断言（这是 ADR-018 决策 6 的延续）。
3. **可用高度由外层量好传进来**，画布不自己往上找父元素：侧栏的父容器是内容撑高的，
   画布再回头撑父容器就成了互相追着长。全屏页把「网格行剩下的高度」量好，交给
   `layoutCollaboration(..., minHeight)` 把行距摊开；**只向上取整、不向下压缩**——
   信息密度可以更松，但不能为了让所有行塞进视口把行距压到标签互相重叠。
4. **标签必须自带底色，胶囊不能取几何中点**。连线是纵向下来的，正好从名字与
   `模型 · Token` 两行字中间穿过去；文字本身不遮光，只靠层级压不住，会看到箭头从笔画
   缝隙里透出来。而一旦标签有了底色，t=0.5 的胶囊中点就正压在这两行字上、被盖掉——
   胶囊的落点改成「上游标签之下、下游圆之上」那条空带的中点（在曲线上采样取最近点）。

**教训**：第一版把「波次」画成了竖向堆叠的卡片、把「串行」写成了卡片之间的一条横线加
`>串行<` 两个字，还配了图例与说明段。数据全对、布局也自洽，但它**不是画布**——用户一眼
就说不是。节点图的价值在于**关系是被画出来的**（谁在谁的下面、哪条线亮着），一旦改成
文字与列表去描述这些关系，再多的字段也只是在解释同一件事。同理，模块标题下面那段
「节点是 Agent 卡片、连线记录上游工具」的功能说明也被删掉了：图自己会说，说明只是噪声。

## 备选方案

- **让侧栏节点继续打开执行轨迹弹窗**。否决：见决策 2。执行台已经承担该入口。
- **保留「竖向堆叠的 Agent 卡片 + 卡片之间的横条」的版式**。否决（本轮）：见决策 7 的教训
  ——那个版式把「并行」写成一行字、把「串行」写成另一行字，等于用文本描述图，读者要先读
  再想；而画布让读者直接看。
- **引入 `reactflow` 之类的图库**。否决：需要的能力只有「画圆点 + 画贝塞尔 + 悬停出面板」，
  参考实现是纯手写 SVG（约 300 行），引一个图库要连带它的布局引擎、缩放平移与样式体系，
  与本站的三级视觉层次对不上。
- **把工具挂在节点卡片里（"这个 Agent 用过什么工具"）**。否决：节点面已经写着 Token，
  而用户真正要问的是「上一步的结果是怎么被加工出来的」——那是边的问题。
  两者都在，等于把同一份工具清单在节点和连线上各写一遍。
- **全屏画布做成新的页面路由**。否决：它是当前任务的**放大**而不是新页面；
  侧栏已有固定位置，加一次导航只是多一次点击，还会让「当前任务」的上下文在页面切换中模糊。
- **在采集侧新增 `agent_id`，前端只认它**。否决（本轮）：要动 C 的采集链路、要重跑历史数据，
  而 `role` 已经能唯一归集。先把读法改对，字段要不要加是另一件事。
- **悬停详情用 JS state（`useState` 记 hover）**。否决：见决策 5。
- **会话列表一次拉全部历史对话的轨迹**。否决：`N 个对话 × 3 个阶段` 的载荷在打开画布时
  一次性拉回来，浪费且慢；按需拉一次是几百毫秒的事。

## 代价（如实记录）

- **侧栏不再一眼看到"进度"**：进度仍在侧栏顶部的整体状态与执行台的卡片上，画布上
  走通的边是蓝的、没走的边是灰虚线。用「这个侧栏不再回答进度问题」换
  「它终于回答了配置与用量问题」。
- **侧栏的节点面只写得出「模型 · Token」**：完整参数表在悬停面板里，鼠标/键盘之外看不到。
  换来的是它在窄栏里终于像一张图而不是一张表。
- **动态链路只有波次与状态，没有逐步骤轨迹**（ADR-019 不落盘，见 §5.17 的边界）：
  画布能显示计划步骤的进度，点开没有轨迹可看。
- **悬停面板的 DOM 常驻**：每个节点多一块详情节点，侧栏 DOM 变大。代价换的是可断言与键盘可达。
- **§5.18 不分页**：一个会话的工作流条数就是它的对话轮数，量级天然小，上限由存储层
  的 `limit`（默认 200）兜底。
- **预览页路由表仍有两处**（`rendercheck/preview_seed.py::ROUTES` 与 `build-preview.py`）：
  本轮又漏了一次，已补；这条纪律没有变。
- **全屏画布的行距跟着窗口高度走**：`minHeight` 由外层量给，超长链路（步骤很多）时
  画布会比一屏高、由页面滚。可预期的代价，比压扁行距好。
